# WebSocket Chat Application

Это приложение — чат, основанный на WebSocket, написанный на Java с использованием библиотеки Jetty.
Позволяет пользователям подключаться к чату, отправлять и получать сообщения в реальном времени.

## Функциональность

- Подключение пользователей к чату через WebSocket.
- Авторизация пользователей с уникальными логинами.
- Отправка публичных сообщений, которые видят все пользователи.
- Поддержка личных сообщений между пользователями.
- Уведомления о подключении и отключении пользователей.

## Требования

Для запуска приложения вам потребуется:

- Java Development Kit (JDK) версии 8 или выше.
- Maven (для управления зависимостями и сборки проекта).

## Установка

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/репозиторий/chat-app.git
   cd chat-app
   ```
## Соберите проект с помощью Maven:
```
mvn clean install
```

## Запуск приложения
Для запуска приложения выполните следующую команду в терминале:

`java -cp target/chat-app.jar server.Start` или запустите по клику на `Run`

Приложение начнет слушать на порту 1400.

Далее, запустите файл index.html в ручную, или кликните по ссылке ниже!

## Использование
Откройте браузер и перейдите по адресу [http://localhost:1400/chat](http://localhost:63342/websocketchat/static/index.html?_ijt=2edvcc3900ue2e5oper4vgpe5j&_ij_reload=RELOAD_ON_SAVE).
Введите свой логин в формате LOGIN:ваш_логин.
После успешной авторизации вы сможете отправлять сообщения, которые будут видны всем пользователям в чате.
Для отправки личного сообщения используйте формат @логин_получателя ваше_сообщение.

## Доработки, выявленные в ходе тестирования

### Дефекты

1. Изоляция комнат не реализована
Параметр ?room= передаётся при подключении, но сервер его не использует: userSessions — одна плоская мапа, broadcast рассылает всем подключённым. Сообщение из приватной комнаты видно участникам публичной и наоборот. Комната существует только как текст, подставляемый клиентом.
Тест: privateMessageIsolation (красный).

2. Сообщение дублируется в истории
index.html кладёт сообщение в messageHistory дважды: в send() при отправке и в onmessage при получении эха от сервера. В истории одна отправка выглядит как две записи в разных форматах.
Тест: checkMessagesHistory (красный).

3. Неавторизованный пользователь пишет в историю от чужого имени
При занятом логине сервер отклоняет подключение, но send() в клиенте не проверяет статус авторизации: сообщение уходит в сокет и записывается в общую историю под именем владельца логина.
Тест: не написан, стоит добавить.

4. Адрес сервера захардкожен в клиенте
ws://localhost:1401/chat зашит в index.html. Приложение неработоспособно на любом другом порту, ServerManager с поиском свободного порта бесполезен, параллельный запуск невозможен.
Проявляется в: checkWSConnectionAndMessages (адрес сравнивается с константой).

5. Нет проверки живости соединения
Ping/pong не настроен, idleTimeout не задан. При потере сети сервер считает клиента подключённым ~5 минут: логин занят, участники не знают об уходе.
Тест: userLeftRoomMessage3 (5 минут, отдельный тег, исключён из основного прогона).

6. onError не освобождает логин
В WebSocketHandler.onError сессия закрывается, но пользователь не удаляется из userSessions. После ошибки логин занят бессрочно.
Найдено чтением кода, тест не написан.

7. Личные сообщения не работают
README описывает формат @логин сообщение, handlePrivateMessage в коде есть, но не вызывается ни из одного места.
Тест: не написан.

8. Приложение не сообщает об обрыве связи
Реакция есть — alert('Соединение закрыто') в ws.onclose, но это модальное окно, а не элемент интерфейса; Playwright закрывает диалоги автоматически. Пользователь не получает информации в самом чате.

### Ограничения тестируемости
В разметке нет data-test атрибутов, у всех сообщений один класс .message. Единственный способ адресовать сообщение — фильтр по тексту.
История общая на весь прогон, накапливает записи всех тестов.
Таймаут разрыва не настраивается — тест на уведомление о выходе при обрыве занимает 5 минут.
Формат сообщений различается у отправителя (Вы:) и получателя (имя в комнате X:), поэтому одно событие проверяется разными строками.

### Техдолг
aspectjweaver 1.9.22 не поддерживает Java 25 — weaving отключён, Allure-шаги не собираются.
Surefire пишет лог не в UTF-8, кириллица в сообщениях о падении нечитаема.
.not().hasText() в privateMessageIsolation заменить на hasCount(0).
source/target 17 в pom.xml заменить на release.
